# 图像压缩终端｜前端改造实施方案 V1.0

## 1. 任务目标

基于现有本地图片压缩软件进行前端重构。视觉采用已确认的 02 号方案：白黄工业科技风，参考《明日方舟：终末地》的工业界面设计语言，但不使用游戏角色、品牌标志或原始游戏素材。

核心任务：用户输入目标文件大小（KB/MB），一次性添加多张图片，使每张输出文件严格小于目标值。默认保持原始宽高，支持批量下载和单张下载。界面改造不得破坏现有压缩算法、文件读取、格式处理和 ZIP 导出逻辑。

## 2. 实施边界

- 首先读取本地项目的现有代码、依赖、运行方式及压缩模块，确认真实组件和事件接口，再执行改造；禁止猜测文件路径、函数名或参数名。
- 优先复用现有技术栈和组件。不要为 UI 重构另建应用或替换压缩引擎。
- 不新增服务器、云端上传、外部字体请求或在线动效依赖。保持离线运行能力。
- 原界面曾显示引擎初始化失败（Invalid URL）。若本地仍能复现，记录实际错误并独立排查；不得用静态“引擎就绪”掩盖失败。
- 保持原功能：目标大小设定、批量导入、单张下载、逐个下载全部、ZIP 打包、清空任务。格式支持以代码实际能力为准。

## 3. 核心视觉规范

### 3.1 设计语言

冷白背景、黑色粗标题、荧光工业黄主操作、灰色边线。通过不对称切角、精密刻度、短斜杠、模块编号和硬朗排版建立工业科技感。整体是实用桌面工具，不是游戏 HUD 或装饰性仪表盘。

| Token | 建议值 | 使用范围 |
|---|---|---|
| 背景 | #F5F6F7 | 全局 |
| 面板 | #FFFFFF / #EEF0F2 | 工作区、控制区 |
| 主文字 | #151719 | 标题、关键数据 |
| 次文字 | #666C73 | 说明、次要信息 |
| 边线 | #D2D6DA | 输入框、列表分隔 |
| 强调黄 | #F5E500 | 主按钮、选中、进度 |
| 强调黄悬停 | #E8D600 | 主操作反馈 |
| 成功 | #267A42 | 达标状态 |
| 警告 | #B66A10 | 无法达标、提醒 |
| 错误 | #B83A38 | 处理失败 |

字体：中文优先使用本地系统无衬线字体（微软雅黑、苹方等），标题 28–32px/700–800，模块标题 20–24px/700，正文 14–16px，辅助标注 12px。数值使用系统等宽字体或 tabular-nums。目标大小数字 48–64px，单位 18–22px。不要依赖在线字体。主要按钮、输入框高度 44–52px；装饰切角 8–14px，边框 1px。普通组件圆角 0–4px；主按钮可以使用单侧或双侧切角。网格仅局部低对比度出现，避免干扰内容。

## 4. 桌面布局

以 1440×900 为设计基准，适配窗口缩放。采用顶部标题栏 + 左侧控制区 + 右侧工作区 + 底部操作区。页面边距 24px，模块间距 20px；左侧约 300–340px（不固定为整屏比例），右侧占剩余空间。低于 900px 时左侧控制区可改为顶部横向参数栏，避免列表横向挤压。长列表在工作区内部滚动，主要操作始终可见。

| 区域 | 内容和行为 |
|---|---|
| 顶部标题栏 | 原创几何压缩图标、图像压缩终端 / IMAGE COMPRESSOR；右侧显示真实本地处理/初始化状态；不额外模拟窗口控制按钮 |
| 左侧参数 | 01 / 压缩参数；目标文件大小输入与 KB/MB 单位；说明“每张输出文件严格小于目标体积”；保持原始宽高；黄色“开始压缩”主按钮 |
| 右侧顶部 | 02 / 批量图像处理；添加图片按钮；支持拖入、点击多选、Ctrl+V（若现有实现已支持） |
| 工作区 | 空状态大拖放框；有文件时收缩为紧凑导入条，下方展示任务列表 |
| 底部操作 | 清空列表、逐个下载全部、打包下载 ZIP；显示任务数量和有效输出总大小。根据真实状态禁用按钮 |

顶部可加入低对比度刻度和折线；左面板标题加黄色斜短条。装饰不应占据操作区域。所有主要控件具有足够对比度和可见焦点。

## 5. 工作区与任务状态

### 初始状态

右侧大面积虚线框，中心是压缩/图片导入图标、标题“拖入图片或点击添加”，辅助说明支持格式与本地处理。保留空白，不展示虚假文件和示例结果。下载按钮禁用；目标值为空或无效时明确提示。

### 已导入状态

导入区缩至约 100–130px；列表占据主体。每行显示缩略图、文件名、格式、像素宽高（可获取时）、原始大小、压缩后大小、状态、单张下载。列宽应确保文件名长时省略，悬停展示完整文件名。默认保留输入顺序；处理前显示等待状态，未完成时输出大小为“—”。

### 压缩中状态

显示真实已完成数量 / 总数量和整体进度；单文件状态展示“等待 / 处理中 / 达标 / 未达标 / 失败”。如果实际算法无法给出阶段百分比，只使用不确定进度动画，不伪造进度数值。避免重复启动任务。保留任务列表和已完成结果；不要让黄色扫描遮挡文字。

### 完成状态

显示每张输出真实字节数对应的显示值、原始体积、缩减比例（可选），绿色“达标”。只有实际字节数严格小于目标值时才显示达标；不要仅以四舍五入后的 KB 显示数判断。已经低于目标值的输入可保留原文件，前提是现有策略允许。不能在维持原始宽高、原格式等限制下达到目标时，明确提示未达标，保留失败原因，不静默改变分辨率或将其标记为成功。ZIP 与批量下载仅包含符合导出规则的有效结果；若有未达标项，明确提示用户。

### 异常状态

无效目标值、文件损坏、不支持格式、压缩失败、引擎初始化失败均显示可读中文原因。错误信息与技术详情分离；单张失败不应阻断其他文件。清空列表仅清理本次任务和资源，不删除本地原文件。

## 6. 入场动画（首次打开）

目标：以“压缩装置启动”为视觉叙事，直接由 UI、CSS、SVG 构成，不使用 MP4 或外部资源。建议总长 1.15 秒，使用 transform、opacity、clip-path，避免持续高 GPU 占用。

| 时间 | 动画 |
|---|---|
| 0–180ms | 冷白底出现，中央四个几何角标由外向内收拢 |
| 180–400ms | 图标内部两层矩形向中心压缩并拼合，黄色小块锁定 |
| 400–620ms | 图标从居中位置过渡到左上标题栏；短黄色横向扫掠揭示标题 |
| 620–880ms | 左侧控制区从左向右显现，右侧工作区淡入并上移约 8px；模块错开约 60ms |
| 880–1150ms | 数值、导入区、按钮依次淡入；顶部状态显示真实结果，动画解除覆盖层 |

规则：只在应用初次启动时播放，任务增删及窗口缩放不重复播放。动画不能作为压缩引擎准备成功的判断。引擎未就绪时显示真实初始化状态。允许点击跳过或接收系统 reduced-motion 偏好；减少动效时直接展示最终界面。动画完成后页面应可立即操作，不保留全屏遮罩或空白等待。

## 7. 交互微动效

- 主按钮 hover：背景轻微加深，右侧箭头向右移动 3px，120–180ms；按下时轻微缩小至 0.98。
- 导入区拖入：虚线框变为实黄色描边，背景淡黄，提示更新；离开立即恢复。
- 新文件行：淡入并移动 4px，80–120ms；批量加入应限制动画次数以避免卡顿。
- 处理进度：黄色实进度与低对比度斜纹；真实完成时状态切换为绿色勾选。
- 下载按钮：短暂反馈“已准备下载”或实际失败原因，不宣称未发生的磁盘保存成功。
- 所有动态效果不改变最终布局，不做长时间循环闪烁。

## 8. 给本地 Agent 的执行顺序

1. 读取现有项目结构、入口文件、压缩引擎和导出模块，记录支持格式、目标单位换算、触发方式、已知错误及可用测试。
2. 保留真实业务逻辑，建立统一视觉变量、布局和组件样式。以方案 02 参考图为视觉基准，先完成静态界面。
3. 将空状态、任务状态、进度、下载和错误反馈绑定现有真实数据。若接口缺失，先说明缺失项，不凭空构造业务 API。
4. 实现入场动画和微动效，优先复用 CSS/SVG。随后进行响应式和键盘操作检查。
5. 使用项目已有运行方式与测试，实际导入多张不同格式与大小的图片进行验证，截图对照参考设计。
6. 汇报变更文件、测试结论、实际截图和未解决的问题。不得在未验证的情况下声称压缩保证达标。

- [ ] 启动、空列表、导入、处理中、成功、未达标、失败状态均能正常显示。
